④ 交互层：让页面活起来

JavaScript 的核心工作只有三件：找到元素、监听事件、更新页面。本页的计数器就是一个真实运行的例子。

1. 找到要操作的元素

浏览器把页面解析成一棵 DOM 树。JavaScript 先查询到节点，才能改变它。

const title = document.querySelector("h1");      // 第一个匹配项
const cards = document.querySelectorAll(".card");  // 所有匹配项
const btn   = document.getElementById("hi");   // 按 id 查找

title.textContent = "新标题";
cards.forEach(card => console.log(card));

脚本要放在 <body> 末尾，或用 DOMContentLoaded 包起来，确保执行时元素已经存在。

2. 监听事件：等用户操作

事件是"发生了什么"的信号：点击、输入、滚动、提交表单都可以监听。三步走：找元素 → 注册监听 → 写处理函数。

btn.addEventListener("click", function () {
  // 用户点击时执行这里
});

input.addEventListener("input", (e) => {
  console.log(e.target.value); // 实时读取输入内容
});
本站点自己就在用：顶部下拉菜单、代码标签切换、目录高亮、返回顶部按钮，全都是 addEventListener 在背后工作。

3. 状态与更新：试试这个计数器

所谓"状态"，就是程序记住的当前数据。下面的计数器把数字存在变量 count 里，每次点击修改它并更新页面显示。

0
> ready
let count = 0; // 状态

function render() {
  countEl.textContent = count; // 把状态反映到界面
}
plusBtn.addEventListener("click", () => {
  count += 1;
  render();
});

这就是前端框架（React、Vue 等）最核心的思想：状态变化 → 重新渲染界面。框架只是把这套流程自动化了。

4. 获取数据：fetch 入门

当页面需要外部数据时，用 fetch 发请求。它是异步的——用 async/await 写起来最清晰。

async function loadData() {
  try {
    const res = await fetch("/api/posts");
    if (!res.ok) throw new Error("请求失败");
    const data = await res.json();
    console.log(data);
  } catch (err) {
    console.error(err); // 网络失败也要给用户提示
  }
}
loadData();

纯静态站点不需要这一步；等到要接评论、表单提交或第三方 API 时，再回来学它也不迟。

5. 出错时怎么办

  • 按 F12 打开控制台，红色报错会给出文件名与行号；
  • Uncaught TypeError: xxx is not a function —— 通常是拼错方法名或元素没找到；
  • 代码没反应，先确认脚本是否成功加载（控制台输入 document.scripts 查看）；
  • 用 console.log() 在关键位置打印变量，是最朴素也最有效的调试方式。
渐进增强原则：页面在没有 JavaScript 时也应当能读到主要内容。JS 用来"增强体验"，而不是承载全部内容。
