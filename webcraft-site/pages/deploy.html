⑤ 部署层：让所有人都能打开

写完代码只是本地文件，部署才是把它变成"一个网站"。这一层解决三件事：放哪里、叫什么、怎么让人放心访问。

1. 上线前检查清单

部署之前，先在本地做最后一轮确认。这一步最常见的问题是大小写和相对路径——本地 Windows 不区分大小写，但多数服务器区分。

  • 所有链接能不能点通？包括导航、页脚、返回顶部；
  • 图片、CSS、JS 是否都使用相对路径且文件名大小写一致；
  • 把站点文件夹整个拷到另一台设备，双击 index.html 是否仍正常；
  • 用手机打开本地文件（或局域网地址），检查响应式效果。
路径经验：首页在根目录用 assets/css/style.css，子目录页面用 ../assets/css/style.css。本站点就是这么组织的。

2. 选择托管平台

对于纯静态站点（就是本教程做出的这类），不需要配置服务器环境，把文件夹上传即可。

方式适合场景说明
静态托管平台个人站点、作品集、文档连接代码仓库后自动部署，通常有免费额度
对象存储 + 静态网站企业官网、活动页上传文件即可，配合 CDN 访问更快
虚拟主机 / 云服务器需要后端、数据库自由度最高，也需要自己维护环境
局域网内部访问演示、内部工具不对外发布，同一网络下通过 IP 访问

部署的本质：把包含 index.html 的整个目录上传，平台会把它映射到一个公开 URL。入口文件一定要叫 index.html。

3. 绑定域名

域名相当于网站的门牌号。购买域名后，需要设置 DNS 解析把它指向托管平台：

记录类型主机记录记录值用途
A@平台提供的 IP让 example.com 指向站点
CNAMEwww平台提供的域名让 www.example.com 指向同一站点

DNS 生效通常需要几分钟到几小时。修改后没生效，先等等再刷新，不要反复改动。

4. HTTPS 与性能

HTTPS 让浏览器与网站之间的传输加密，地址栏出现小锁标志。现代托管平台基本都提供免费证书，开启后记得强制 HTTP 跳转到 HTTPS。

  • 压缩图片：先缩尺寸再上传，质量够用即可；
  • CSS/JS 文件合并压缩，减少请求数量；
  • 给脚本加 defer，不阻塞页面渲染；
  • 用浏览器无痕模式测试一遍，排除缓存干扰。
不要过早优化：一个内容清晰的网站，比一个加载快 0.1 秒但没有价值的网站更有用。先把内容做好。

5. 上线不是终点

网站发布后，保持一个简单循环：观察 → 收集 → 修改 → 再发布。

  • 问身边三个人：他们能在 10 秒内找到想看的内容吗？
  • 定期点击全站链接，避免内容更新后出现死链；
  • 把每次修改都留一个备份或版本记录，出错时能回退；
  • 每三个月回看一次目标：网站还在服务于最初那个目的吗？
