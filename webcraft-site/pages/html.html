② 结构层：用 HTML 搭骨架

HTML 不是"写网页外观"，而是"告诉浏览器这份文档里有什么"。结构对了，样式和交互才有可靠的落脚点。

1. 每份 HTML 的骨架

下面这 10 行是几乎所有页面的起点。新建 index.html，把这段粘进去：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>页面标题</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <!-- 页面可见内容写在这里 -->
  <script src="app.js"></script>
</body>
</html>
  • lang="zh-CN" 声明页面语言，帮助搜索引擎与读屏软件；
  • charset="UTF-8" 保证中文不乱码；
  • viewport 让页面在手机上按真实宽度渲染——漏掉它，移动端布局会失效；
  • 样式表放 <head>，脚本放 <body> 末尾，避免阻塞渲染。

2. 语义化：让标签表达含义

同样是一个标题，<h1> 告诉浏览器"这是主标题"，而 <div class="big"> 什么也没说。语义化结构对 SEO、可读性和辅助技术都更友好。

标签用途
<header>页头或区块头部，常放 Logo、导航
<nav>主导航链接集合
<main>页面主体，一页只出现一次
<article> / <section>独立内容 / 主题分组
<aside>侧边栏等辅助内容
<footer>页脚信息
<h1>~<h6>标题层级，一页通常只有一个 h1
判断方法：去掉所有 CSS 后，页面还能不能清晰读出内容层次？能，说明结构合格。

3. 图片与链接

图片必须写 alt：既是无障碍要求，也是图片加载失败时的兜底文案。装饰性图片用 alt="" 明确告诉读屏软件跳过。

<!-- 内容图片：描述内容 -->
<img src="team.jpg" alt="团队在会议室讨论方案" width="800" height="500">

<!-- 站内链接 / 站外链接 -->
<a href="about.html">关于我</a>
<a href="https://example.com" target="_blank" rel="noopener">外部站点</a>

给图片写上 width 和 height，浏览器可以提前预留空间，避免加载时页面跳动。

4. 表单的基本功

表单是网站收集信息的主要方式。每个输入框都要有 <label> 关联，点击标签文字就能聚焦输入框：

<form action="/submit" method="post">
  <label for="email">邮箱</label>
  <input id="email" name="email" type="email" required>
  <button type="submit">订阅</button>
</form>

type="email" 会自动调起合适的手机键盘并做基础校验；required 阻止空值提交。

5. 可访问性：三个立即能做的改进

  • 用键盘 Tab 走一遍全站，确认所有可点击元素都能被聚焦；
  • 图片补 alt，按钮写清楚文字，避免"点击这里"；
  • 标题按 h1 → h2 → h3 顺序使用，不要为了字号跳级。
常见误区：用 <div onclick="..."> 做按钮。它没有键盘可用性，应使用原生 <button>。
